# CineDairy для Android

Первая Android-версия использует общий интерфейс CineDairy внутри WebView. HTML, CSS и JavaScript входят в APK, поэтому запуск не зависит от доступности сайта. Это устанавливаемое гибридное приложение, а не ярлык сайта. Требуется Android 8.0+ и актуальный Android System WebView.

## Обновление 0.2.0: интерфейс для телефона

Пять разделов нижней навигации, отдельная панель «Ещё», контекстная кнопка добавления, компактная коллекция, выдвижные фильтры, полноэкранные формы и сохранение позиции разделов. Основные области нажатия — минимум 48 × 48 CSS px при масштабе WebView 1:1. Рекомендации и принятые решения описаны в [PHONE_DESIGN.md](PHONE_DESIGN.md).

## Что работает

- Фильмы и сериалы, история просмотров, оценки, заметки, цитаты, подборки, планы, фильтры и статистика — тот же функционал, что на сайте.
- Гостевой режим без регистрации и без сети, в том числе при первом запуске.
- Вход в существующий аккаунт по email/паролю или коду; регистрация по email. Эти операции требуют доступного сервера.
- После первого успешного входа архив аккаунта сохраняется на телефоне. Его можно читать и редактировать без сети и при ошибках сервера, затем закрывать и снова открывать приложение.
- Автоматическая отправка изменений при открытом приложении, восстановлении соединения и возврате из фона; ручная кнопка «Синхронизировать».
- Импорт JSON через системный выбор файла, экспорт JSON и карточек цитат PNG через системный диалог сохранения.

Для подключения используется существующий `https://cinedairy.ru` и его API. Обновлять сервер ради этой версии не требуется. Изменения общей `account.js` включают автономный режим **только в APK**; сайт сохраняет прежнюю политику хранения аккаунта.

## Установка и первая проверка

1. В GitHub откройте Actions → **Android APK and offline checks** → успешный запуск → артефакт **CineDairy-Android-debug**.
2. Распакуйте ZIP, перенесите `app-debug.apk` на телефон и установите. Android может попросить разрешить установку из используемого файлового менеджера.
3. Откройте CineDairy. Можно сразу пользоваться гостевым архивом или войти в аккаунт сайта по email.
4. Дождитесь статуса «Всё синхронизировано».
5. Включите авиарежим, добавьте фильм/просмотр/цитату, закройте приложение, запустите снова. Записи должны остаться.
6. Отключите авиарежим, откройте приложение и нажмите «Синхронизировать». Проверьте записи на сайте.

Debug APK предназначен для проверки. Для публикации и стабильных обновлений нужен release APK/AAB с постоянным ключом подписи владельца. Не удаляйте приложение для смены подписи без экспорта: удаление приложения удаляет его локальные данные. Debug-ключ GitHub runner может меняться между сборками.

## Сборка в Android Studio

Откройте папку `mobile/android`, выберите JDK 17 и установите Android SDK Platform 35 / Build Tools 35.0.0. Дождитесь Gradle Sync, затем используйте Build → Generate App Bundles or APKs → Generate APKs либо терминал:

```sh
# Из mobile/android
./gradlew assembleDebug lintDebug
# В Windows
.\gradlew.bat assembleDebug lintDebug
```

Результат: `mobile/android/app/build/outputs/apk/debug/app-debug.apk`.

Gradle Wrapper 8.11.1 и AGP 8.9.2 закреплены. Задача `prepareWeb` берёт разрешённые файлы интерфейса из корня репозитория; ручное копирование не нужно. Удалённая загрузка интерфейса при запуске не используется. Для отдельного тестового HTTPS-сервера можно передать `-PcinedairyHost=staging.example.org`. Приложение намеренно не допускает HTTP и произвольный адрес сервера из интерфейса.

## Как устроена автономность

`mobile/web/offline.js` хранит в одной атомарной записи localStorage: ID аккаунта и публичные настройки входа, текущий архив, подтверждённую серверную ревизию, признак неотправленных изменений и последний отправляемый снимок. Пароли и CSRF-токен туда не записываются; сессия работает через обычную защищённую cookie сервера.

Интерфейс подтверждает изменение только после локальной записи. Пока сервер недоступен, изменения объединяются в последний снимок архива. При подключении приложение сначала проверяет ID сессии, затем получает серверную ревизию, после чего выполняет условный PUT. Одновременно работает не больше одной синхронизации. Правки во время отправки остаются в очереди. Если ответ потерян после успешного PUT, сохранённый отправляемый снимок сопоставляется с сервером — это также работает после перезапуска.

При ошибках сети/5xx/429 применяются повторы с задержкой до 5 минут. Отсутствие интернета определяется по результату запроса, а не только значку Wi-Fi. 401/403 требуют повторного входа, 400/413/422 показываются как отказ сервера. Во всех этих случаях локальный архив остаётся доступен. При закрытом приложении постоянного фонового процесса нет: синхронизация возобновляется при открытии.

Если архив изменился на двух устройствах, автоматическая замена запрещена. Пользователь скачивает обе версии и явно выбирает телефонную либо серверную. Перед выбором обе копии сохраняются локально; скачать их можно в аккаунте. Для отправки выбранной локальной версии снова используется проверка ревизии: новые изменения сайта не будут молча затёрты. Слияние отдельных записей пока не реализовано.

## Ограничения первой версии

- Вход через Яндекс внутри APK не включён. Если аккаунт создан через Яндекс, сначала привяжите email на сайте, затем войдите с ним в приложение. Новый email-аккаунт с другим ID не объединяется автоматически.
- Автопоиск новых фильмов требует сети и работающего сервера; ручное добавление доступно всегда.
- Постеры используют стандартный кэш WebView. Не загруженный или вытесненный из кэша постер заменяется оформленной заглушкой; метаданные, оценки и записи сохраняются независимо от изображения.
- Локальное хранилище WebView имеет ограниченный объём. При нехватке места запись не подтверждается и предыдущая версия сохраняется. Это не неограниченное хранилище; для больших архивов следующим шагом будет SQLite/Room.
- Архив доступен человеку, разблокировавшему телефон; отдельного PIN/биометрии в приложении нет. Android backup отключён. Локальная копия и сессия находятся в приватном каталоге приложения.
- Явный выход удаляет локальную копию аккаунта; при неотправленных изменениях сначала требуется синхронизация. Отдельное удаление локальной копии возможно после подтверждения. Гостевой архив переносится в аккаунт только по явному действию.

## Проверки

```sh
npm ci
npm test
npx playwright install chromium
npm run test:android
npm run test:ui
```

`tests/offline.test.cjs` проверяет перезапуск, 503, потерянный ответ PUT, изменения во время отправки, конфликты, смену аккаунта, переполнение диска, повреждение данных и параллельные запросы. `tests/android-ui.test.cjs` открывает комплект APK в браузере с подменённым сервером и проверяет пользовательские сценарии. Workflow `android.yml` выполняет проверки, Android Lint и сборку APK. Браузерные проверки не заменяют проверку системного выбора/сохранения файлов, Back и экранной клавиатуры на телефоне.
